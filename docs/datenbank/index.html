Die Adresse der REST-API besteht aus vier Teilen (Skript, Abbildung zur URL):

Ein Paket für HTTP. Flutter selbst kann keine Webanfragen – das übernimmt das Paket http. Alle Zugriffe auf die Datenbank sammeln Sie in webRequest.dart.

Android braucht eine Erlaubnis für Anfragen an http://-Adressen:

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET"/>
    <application
        android:label="meine_app"
        android:usesCleartextTraffic="true"
        ...>

Ein einzelner Datensatz lässt sich direkt in eine Map umwandeln. Die Daten kommen zeitverzögert an – deshalb ist die Methode async und gibt ein Future zurück:

import 'dart:convert';

import 'package:http/http.dart' as http;

// IP-Adresse Ihres Raspberry Pi – nur hier ändern
const String ip = '192.168.0.10';

// einen Datensatz (den ersten) der Tabelle flutterTB abrufen
Future<Map> loadContactData() async { // asynchrone Methode
  var url = Uri.parse('http://$ip/php-crud-api/api.php/records/flutterTB/1');
  var response = await http.get(url); // await wartet, bis die Daten da sind
  var responseJson = jsonDecode(response.body); // wandelt den JSON in eine Map um
  return responseJson;
}
BausteinBedeutung
Future<Map>die Map kommt später – wie eine Abholnummer
await http.get(url)wartet, bis der Server geantwortet hat – die App bleibt bedienbar
jsonDecodewandelt den JSON-Text in eine Dart-Map um

Die IP steht nur einmal oben ($ip in der Adresse). Im Skript steht sie in jeder Adresse – so müssen Sie sie nur an einer Stelle ändern.

Erklärt – was passiert hier?

Warum keine Map mehr? Bisher hatte ein ToDo zwei Eigenschaften (checkbox, name), der Name war der Schlüssel. Für die Datenbank braucht jedes ToDo eine eindeutige id. Das erlaubt die Map nicht – deshalb eine Liste von Objekten.

class ToDoListObject {
  int id;
  String name;
  bool checkbox;

  ToDoListObject(this.id, this.checkbox, this.name);
}

Damit aus der Datenbank und aus dem Alert-Dialog Daten übergeben werden können, wird diese Klasse benötigt. Achtung: Im Konstruktor steht checkbox vor name.

void addItem(String itemName) {
  setState(() {
    ToDoListObject newtodo = ToDoListObject(todos.length + 1, false, itemName);
    todos.add(newtodo);
  });
  Navigator.of(context).pop();
}

void deleteItem(int id) {
  setState(() {
    todos.removeWhere((element) {
      return element.id == id;
    });
  });
}

void checkBoxDone(int id) {
  setState(() {
    ToDoListObject item = todos.firstWhere((element) => element.id == id);
    item.checkbox = !item.checkbox;
  });
}

  • removeWhere entfernt alle Elemente, für die die Bedingung stimmt.

// Abruf der Daten für die ToDoListe
Future<List> loadDataToDo() async {
  var url = Uri.parse('http://$ip/php-crud-api/api.php/records/ToDoTB/');
  var response = await http.get(url);
  var responseJson = jsonDecode(response.body);
  var toDoList = responseJson['records'];
  return toDoList;
}
// Senden eines kompletten Datensatzes an die Datenbank
Future<void> sendDS(ToDoListObject newItem) async {
  var url = Uri.parse('http://$ip/php-crud-api/api.php/records/ToDoTB/');
  await http.post(url, body: {
    'id': newItem.id.toString(),
    'checkbox': '0',
    'name': newItem.name,
  });
}
// Löschen eines Datensatzes – die id steht im Pfad
Future<void> deletDS(ToDoListObject newItem) async {
  var url = Uri.parse(
      'http://$ip/php-crud-api/api.php/records/ToDoTB/' + newItem.id.toString());
  await http.delete(url);
}
// Update eines Attributes aus dem Datensatz
Future<void> updateDS(ToDoListObject updItem) async {
  var url = Uri.parse(
      'http://$ip/php-crud-api/api.php/records/ToDoTB/' + updItem.id.toString());
  int updI = updItem.checkbox ? 1 : 0; // Kurzschreibweise
  await http.put(url, body: {'checkbox': updI.toString()}); // put = Update
}

    ToDoListObject newItem =
        ToDoListObject(element['id'], element['checkbox'], element['name']);
    todos.add(newItem); // legt die geladenen Werte in die Liste todos
  }
  setState(() {});
}

Die Spalte checkbox kommt als 0/1 statt true/false an. Legen Sie sie als BOOLEAN an – oder schreiben Sie element['checkbox'] == true || element['checkbox'] == 1.

Auftrag

  1. addItem: Nach todos.add(newtodo) das neue Objekt mit sendDS(newtodo) an die Datenbank schicken.
  2. deleteItem: Das Objekt mit firstWhere suchen, mit deletDS(…) in der Datenbank löschen, dann aus der Liste entfernen.

Erklärt – was passiert hier?

Die Oberfläche bleibt, wie sie ist. Jede Methode, die Daten verändert, gibt die Änderung zusätzlich an die Datenbank weiter:

void addItem(String itemName) {
  setState(() {
    ToDoListObject newtodo = ToDoListObject(todos.length + 1, false, itemName);
    todos.add(newtodo);
    sendDS(newtodo); // Create
  });
  Navigator.of(context).pop();
}
void deleteItem(int id) {
  setState(() {
    ToDoListObject item = todos.firstWhere((element) => element.id == id);
    ToDoListObject deltodo = ToDoListObject(item.id, item.checkbox, item.name);
    deletDS(deltodo); // Delete
    todos.removeWhere((element) {
      return element.id == id;
    });
  });
}
void checkBoxDone(int id) {
  setState(() {
    ToDoListObject item = todos.firstWhere((element) => element.id == id);
    item.checkbox = !item.checkbox;
    ToDoListObject upttodo = ToDoListObject(item.id, item.checkbox, item.name);
    updateDS(upttodo); // Update
  });
}

Tipp – Neues ToDo ist nach dem Neustart weg?

Steht es im Browser in ToDoTB? Wenn nicht: Gibt es die id schon? Siehe „Kritisch betrachtet“.

Kritisch betrachtet

Die id todos.length + 1: Sie haben die ToDos 1, 2 und 3 und löschen ToDo 2. Das nächste neue ToDo bekommt die id 3 – die gibt es schon. Die Datenbank lehnt den Datensatz ab, die App zeigt ihn trotzdem an. Bessere Lösungen: die höchste vorhandene id + 1 – oder die Datenbank vergibt die id selbst (AUTO_INCREMENT) und die API meldet sie nach dem POST zurück.

Keine Fehlerprüfung: Die Methoden warten nicht auf die Antwort des Servers. Ist der Pi aus, zeigt die App Änderungen, die nie gespeichert werden.

Merke: POST legt an, GET liest, PUT ändert, DELETE löscht – die id in der Adresse sagt, welcher Datensatz gemeint ist.

4 · async und await

Eine Anfrage ans Netz dauert. Statt die App anzuhalten, liefert sie ein Future – ein Versprechen auf ein späteres Ergebnis.

Future<List> loadContactData_L() async {   // async: hier darf gewartet werden

void loadDataFromDB_L() async {
